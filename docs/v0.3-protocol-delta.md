# LinkNote v0.3.0 实时协议增量（实现约定，2026-10-24）

> 目标：把 DO 成本降回免费额度、修正在线判定、把"收到"与"保存成功"分开、让手机知道"电脑在线 ≠ 可以生成"。
> 约束：Relay 向后兼容 0.2.2 客户端；新客户端也兼容旧 Relay。不改 REST 路径，只加 WS 消息/字段与内部接口字段。

## 1. 心跳与在线（成本优化）

### Agent 侧
- **删除 25s 应用层 JSON ping**。改用 WebSocket 协议 ping：`websockets.connect(..., ping_interval=25, ping_timeout=20)`。
  Cloudflare 运行时自动应答协议 ping，不唤醒 DO、不计请求。
- 保留对服务端 JSON `ping` 的 `pong` 响应；收到 `probe` 回 `probe_ack`。

### Relay 侧
- **只有存在手机 socket 时才设置 30s alarm**；没有手机时：不设 alarm、不主动 ping、不写 SQL。
  - `online` 判定：agent socket 存在即 online；`webSocketClose/Error` 立即 offline。
- 手机连接时：
  - 若 agent socket 存在但 `now - last_seen > 15s`，立即向 agent 发 `{"type":"ping","ts":...}`；
    同时设 3 秒 `setTimeout`，超时且无 pong → 推 `presence {online:false}`（标记 offline，不强行 close）。
  - 有 pong → `presence {online:true}`，并广播 `ready/issues`。
- 有手机连接期间的 alarm（30s）：
  - 向 agent 和 phone 发 `ping`；agent 回 `pong` 刷新内存 `last_seen`；
  - alarm 内若 `now - last_seen > 60s` → 关闭 agent socket（4002）+ offline；
  - alarm 末尾若仍有 phone/agent socket 就重新 `setAlarm`。
- `last_seen` 只放内存；`online`/`last_seen_at` 只在 online↔offline 跃迁时写 `room_meta`。**禁止每条消息写 SQL。**
- 兼容旧 agent：旧 agent 的 JSON ping 照常回 `pong`；但新逻辑不再依赖它。

### 消息
- Server → Agent：`{"type":"ping","ts":number}`，`{"type":"probe","ts":number}`
- Agent → Server：`{"type":"pong","ts":number}`，`{"type":"probe_ack","ts":number}`

## 2. ack_note：区分"收到"与"已保存"

- Phone → Relay：`{"type":"ack_note","task_id":string,"persisted":boolean}`；**缺省 `persisted=true`**（兼容旧客户端）。
- Relay：
  - `persisted !== false`：删除 `undelivered_notes` 中该 task；向 Agent 转发 `{"type":"ack_note","task_id","persisted":true}`。
  - `persisted === false`：**不删** `undelivered_notes`；向 Agent 转发 `{"type":"ack_note","task_id","persisted":false}`。
- Agent：
  - `persisted !== false`：`outbox.ack_note(task_id)`（只清 outbox，`notes/` 文件保留）。
  - `persisted === false`：保留 outbox；按 30s / 2min / 10min 最多重发 3 次；之后等 `note_request` 或重启补发。
- Phone：只有 `noteCache.put` 成功才 ack `persisted:true`；失败 ack `persisted:false`，页面提示"未保存到手机，可重试"。

## 3. readiness：在线 ≠ 可生成

- Agent → Relay（收到 `hello` 后立即发一次，变化时重发）：
  ```json
  {"type":"agent_ready","ready":false,"issues":[
    {"code":"model_not_configured","label":"未配置 AI 模型"},
    {"code":"engine_unreachable","label":"BiliNote 引擎不可用"}
  ]}
  ```
- 初始 issues 代码：
  - `model_not_configured`：`provider_id` 或 `model_name` 为空；
  - `engine_unreachable`：BiliNote `/api/health` 失败（超时 ≤2s）；
  - 预留：`ffmpeg_missing`、`agent_paused`。
- Relay：内存保存 `ready/issues`，状态变化时写 `room_meta`；在以下位置返回：
  - phone `hello`：`ready`, `issues`
  - `presence`：`online`, `last_seen`, `ready`, `issues`
  - `/internal/presence`：同上（REST `/agent/me` 透传）
- 缺字段视为 `ready:null`（未知），UI 显示"在线"。
- Phone：在线但 `ready===false` 时显示"电脑在线 · 需要处理"；可展开 issues。
- Desktop：主窗口顶部横幅用本地状态 + presence 显示"已准备好接收视频"或"需要处理 N 项"。

## 4. 验收

1. 无手机连接、30 台常在线 24h：除连接/断线事件外，alarm/主动 ping 为 0。
2. 手机打开 3 分钟：每台约 6–8 次 alarm/ping 请求。
3. 手机连上：alive agent 3s 内 `online=true` 且 `ready` 正确；kill agent 后 ≤90s `online=false`（30s alarm + 60s stale + 3s 探活）。
4. 手机缓存失败：`ack persisted=false`，Agent 保留 outbox 并重试；手机重试保存成功后 outbox 清空。
5. 旧 0.2.2 Agent + 新 Relay、新 Agent + 旧 Relay、新 PWA + 旧 Relay 都能正常工作。
6. 隔离不回归：所有 D1 查询仍带 `agent_id`；A 收不到 B 的任何消息。

## 5. 测试要求

- `relay/tests/contract.e2e.mjs`：新增/调整 ack persisted、agent_ready 字段、probe、alarm 仅在手机在线时设置、无手机不写 SQL 的断言。
- `pc-agent` pytest：无应用层周期 ping；pong/probe_ack；agent_ready 上报；ack persisted=false 保留 outbox 并重试；旧测试全绿。
- PWA 测试：ack persisted、缓存固定/徽标、ready UI、断网重试。
