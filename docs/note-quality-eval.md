# LinkNote 笔记质量评测方案（20 条真实学习视频）

> 目的：证明"生成的笔记值得用户再打开一次"。当前仓库里的样例（歌曲 MV、18 秒短视频）只证明链路跑通，不证明学习价值。本方案用于在承诺付费之前拿到真实证据。
>
> 使用方式：人工/半自动跑 20 条视频，逐篇按评分表打分，记录问题。评测脚本可复用 `scripts/e2e-real-claim.mjs` 的链路。

## 1. 视频覆盖矩阵（各 5 条，共 20）

| 类别 | 例子 | 考察点 |
|---|---|---|
| 中文讲解（口播/知识区） | B 站科技区 UP 主讲解、网课 | 中文术语、章节结构、关键结论 |
| 英文技术内容 | YouTube 技术演讲、教程 | 英文转写质量、术语翻译、代码/命令准确 |
| 长讲座/课程（>45 min） | 公开课、会议 Keynote | 长文本不丢主线、分章、摘要不塌 |
| PPT / 屏幕演示 | 教程录屏、编程演示 | **默认音频模式的盲区**：图表/板书/屏幕细节能否被补上 |

每条视频记录：来源 URL、平台、时长、语言、是否有 PPT/屏幕内容、是否需要登录。

## 2. 单篇评分表（每篇 1–5 分）

| 维度 | 5 分标准 | 常见失分 |
|---|---|---|
| **1. 概括准确** | 看完能说清视频讲了什么、结论是什么 | 编造论点、把举例当结论 |
| **2. 关键点覆盖** | 核心概念/步骤/数据齐全，无重大遗漏 | 只留开头，长视频尾部丢失 |
| **3. 术语准确** | 专业名词正确，不误译 | 英文术语乱译、同一名词前后不一致 |
| **4. 可核对** | 含来源 URL、章节时间戳（或可定位的结构），有疑问能回到原视频 | 没有来源、没有时间锚点、结论无出处 |
| **5. 可复用** | Markdown 结构清晰（标题/列表/表格），适合进 Obsidian；含 frontmatter | 一段大散文、无层级、无元数据 |

**判定**：
- 单篇 ≥ 18 分且没有任一维度 ≤ 2 → 合格
- 20 篇中合格 ≥ 12 篇（60%）→ 笔记质量通过，可进入招募
- < 12 篇 → 先修笔记质量，不急着招募付费

## 3. 必记录的元数据（frontmatter 对齐项）

每篇生成后检查头部是否包含：title、source_url、platform、author（可空）、created_at、output_language、video_duration、model/version。缺失项记录，用于校准 Agent 的 frontmatter 输出。

## 4. 盲区专项（PPT/屏幕演示）

默认是"音频讲解笔记"模式。对屏幕演示类视频额外记录：
- 是否出现"语音转对了但关键视觉信息没记到"（如图表数值、代码、命令、公式板书）。
- 若 >50% 的屏幕演示类视频在此项失分，明确把边界写进产品文案与默认模板，**不要**在首发承诺"看懂画面"。

## 5. 运行与记录

1. 选视频并填矩阵 → 在手机端提交 → 等 Agent 生成（真实 BiliNote 引擎 + 真实模型）。
2. 生成后导出 Markdown，按评分表逐项打分，存到 `assets/eval/{编号}-{标题}.md` + `assets/eval/scores.csv`。
3. 附问题截图/原文片段，用于改模板与提示词。
4. 评测期间不改代码；把发现的问题收集后统一改进，再复测失败样本。

## 6. 成本提示

- 每篇涉及下载 + 转写 + LLM 调用，使用你自己的 API Key 与转写方式。
- 长讲座视频的 LLM token 成本最高，先用 1–2 条试跑，确认成本再全量。

## 7. 产出

- `assets/eval/scores.csv`：20 行 × 5 维度分。
- 一段结论："当前默认模板的强项/盲区/下一步改什么"。
- 3–5 篇最佳样例（导出的 Markdown）→ 用于招募 20–30 名用户的演示与展示。
