# Relay 成本模型（2026-10-24 核对）

> 结论：**“免费计划可扩展到千台常在线”是错的**。v0.2.2 的实现约 **32 台常在线**就会触到 Cloudflare 免费额度；免费额度是**硬失败**（当天该类型操作报错），不是自动扣费。v0.3.0 改成“只有手机在线时才心跳”后，1,000 台常在线也能留在免费额度内；生产/内测仍建议开 Workers Paid **$5/月** 兜底。

## 1. 官方额度与计费口径（已核对）

来源：[Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)

- 免费计划 DO（SQLite）：**100,000 请求/天**、13,000 GB-s/天、5,000,000 行读/天、**100,000 行写/天**、5 GB 存储；超限**硬失败**。
- **alarm 调用 = 1 次完整请求**；`setAlarm()` = **1 行 SQLite 写入**；WebSocket 入站消息 20:1 折算，**不适用于 alarm**。
- 出站 WS 消息、协议 ping 帧不计费；`setWebSocketAutoResponse` 不唤醒 DO、不计时长（是否计入请求指标文档未写死，需实测）。
- Hibernation 只免“时长”，不免 alarm/请求/写入。
- Workers Paid：$5/月；DO 请求 1M 含在月费内，之后 $0.15/M；行写 50M/月含，之后 $1.00/M。

## 2. v0.2.2 实测口径（每台常在线 Agent / 天）

| 项 | 数量 | 计费 |
|---|---:|---|
| 30s alarm | 2,880 | 2,880 请求 + 2,880 行写（每次 setAlarm） |
| Agent 25s 应用层 ping | 3,456 条 | ×20:1 ≈ 173 请求 |
| 合计 | ≈3,053 请求 + 2,880 行写 | 约 3% 的免费请求额度/台/天 |

- 免费上限 ≈ **32 台常在线**（33 台即请求超限；行写 34 台超限）。
- 30 台：请求 91.6%、行写 86.4%，**内测随时硬失败**。
- 1,000 台：约 3.05M 请求/天（30 倍超额）；付费约 **$55/月**，其中约 **$37 是 setAlarm() 行写**，比请求费更贵。

## 3. v0.3.0 目标口径

- Agent 用 **WebSocket 协议 ping**（`ping_interval=25`），Relay 不唤醒、不产生请求。
- Relay **只在有手机 socket 时**启用 30s alarm；没有手机时不 ping、不写 SQL。
- `last_seen` 只存内存；`online`/`last_seen_at` 仅在状态跃迁时写 `room_meta`。
- 手机连接时对 Agent 做一次 ping + 3s 探活；有手机期间的 alarm 才负责断线兜底（60s）。

估算（1 台 = 每天打开手机 5 次、每次 3 分钟）：

| 项 | 数量/天 |
|---|---:|
| alarm（仅手机在线） | 5 × 6 = 30 请求 + 30 行写 |
| 手机/Agent ping（仅手机在线） | 约 6 请求 |
| 连接/断线事件 | 少量 |
| **合计** | **≈36 请求 + 30 行写/台/天** |

- 1,000 台：约 36,000 请求/天（**36% 免费额度**）、30,000 行写/天（30%），可留在免费额度内。
- 付费兜底：约 **$5/月**（$5 账号费 + 少量用量）。
- 结论：**不要为了省 $5 把产品押在免费额度上**；免费额度只适合个人 1–3 台。

## 4. 监控与验收

- 上线前用 `wrangler tail` + Cloudflare 仪表盘记录：DO 请求、alarm 次数、行写、D1 写、WS 消息数。
- 压测：本地脚本模拟 30/100/1000 台 Agent 只连接不操作 → 观察请求/写入增长；再模拟手机打开 3 分钟。
- 告警：免费额度余量 <50% 时升级/优化；生产环境直接 Workers Paid。
- 任何“每 N 秒唤醒每个 DO”的定时器都要先算账：**1,000 个 DO × 86,400/N 次/天**。

## 5. 历史口径更正

- 旧 README/部署文档写“个人/小团队免费额度内 $0”，这只对 1–3 台设备成立；30 台已接近硬上限。
- 旧架构文档写“Hibernation 空闲不计时长”容易让人误以为“免费”，已改为同时列出请求与行写成本。
